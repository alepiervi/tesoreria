# RCA — Demo/test invoices ("fatture di prova") arriving in production

**App:** gestione-tesoreria-1 (Nureal-Amministrazione) · FastAPI + MongoDB
**Active run:** 5c630974-3cba-4456-90b1-b94bd7f94541 · DB: gestione-tesoreria-1-tesoreria
**Investigation:** read-only (list_secrets + mongo_query). No personal data reproduced below.

## Problem statement
User reports test/demo invoices arriving in the invoice import, suspected to come from the demo "cassetto fiscale" SDI sync.

## Root cause (confirmed)
The **production backend is running with the DEMO providers enabled**, not the real/none providers the repo expects. Verified via `list_secrets` (values never revealed — matched against expected strings):

| Secret | is_empty | Production value |
|---|---|---|
| SDI_PROVIDER | false | **"demo"** (matches_expected=true for "demo"; false for "none") |
| BANKING_PROVIDER | false | **"demo"** |
| PAYMENTS_PROVIDER | false | **"demo"** |
| SEED_DEMO | false | **"false"** (matches_expected=true) |

So `SDI_PROVIDER=demo` in production — even though `backend/.env` in the repo sets `SDI_PROVIDER=none` (and the `app/config.py` default is `'demo'`). The demo SDI provider fabricates fake "cassetto fiscale" invoices on every sync.

### Why prod ≠ repo
Custom secrets are carried forward from the previous PRODUCTION run on each redeploy; the repo/preview `.env` only ADDS new keys — it never overwrites a key already set in prod. `SDI_PROVIDER` already existed in prod as `"demo"`, so the later repo change to `none` never took effect. `SEED_DEMO=false` is fine; the demo data is coming from the live SDI sync, not from seeding.

## Evidence in the database
- `audit` collection: **4 entries with action `sdi_sincronizzato`**, each `details.nuove = 1` (one new invoice imported per sync). Timestamps (UTC):
  - 2026-11-16T12:32:19Z
  - 2026-11-16T12:35:01Z
  - 2026-11-16T12:35:41Z
  - 2026-11-16T15:20:24Z
- `invoices` collection: currently **empty** (count 0 — collection exists). Demo counterparty/iban filter (`counterparty_name` in Omega Srl / Sigma Forniture Srl / Tau Logistica Spa, or iban IT60X0542811101000000123456): **0 right now**.
- `invoice_xml`, `documents`: empty. `transactions.source` distinct = ["import"] only.

Interpretation: the demo SDI sync *is* actively creating invoices (audit proves 4 imports, newest 15:20Z 2026-11-16). The `invoices` collection being empty now indicates the imported demo invoices were deleted after import — but because the demo provider is still active, each new sync re-creates them (the "they keep arriving" symptom). min/max created_at on demo invoices could not be computed because none are currently stored.

## Fix
1. **User (Secrets) — primary.** In Deployment Panel → Secrets, set `SDI_PROVIDER=none` (and set `BANKING_PROVIDER` / `PAYMENTS_PROVIDER` to the intended real/none values instead of `demo`), then redeploy. This stops the demo cassetto-fiscale sync from generating fake invoices. After redeploy, delete any residual demo invoices.
2. **Code (hardening) — optional/defense-in-depth.** The `app/config.py` default of `'demo'` for these providers is unsafe for a production financial app. Changing the default to `'none'` won't fix the current issue (the prod secret is explicitly `"demo"`), but E1 should flip the default to fail-safe so a missing value can never silently enable demo mode.
